## 9. Initial Project Registry

The MVP begins with seven project buildings.

### 9.1 Viasat

**Category:** Professional  
**Visual weight:** Major / one of the tallest buildings  
**Confidential:** Yes  
**Status:** Current work

Public case study must be sanitized.

Do not include:

- screenshots of internal products;
- proprietary UI;
- private data;
- internal architecture unless specifically approved;
- implementation details that should not be public.

The public project/team name "Security Scorecard" must only be used if Adrian has confirmed that it is acceptable to publicly associate with his work.

Otherwise use a broader description such as:

> Internal security software at Viasat.

### 9.2 HR / ATS ERP

**Category:** Professional / Tech Lead  
**Visual weight:** Major  
**Confidential:** Likely internal/private

The case study should emphasize:

- technical leadership;
- project ownership;
- architecture;
- multi-tenancy;
- Node.js / Express;
- PostgreSQL;
- React / TypeScript;
- AI-assisted candidate matching;
- resume ingestion;
- delivery from scratch to production;
- team leadership.

Only publish details that are safe to disclose.

### 9.3 AI Automation Experience

**Category:** Professional specialization / technical work  
**Visual metaphor:** Research/technology building

This building can aggregate meaningful AI automation work if there is not a single public product that represents it.

Potential themes:

- LLM integration;
- MCP;
- automation;
- structured tool use;
- AI-assisted workflows;
- production-oriented AI features.

This should not become an "AI buzzword" section. Every claim should be tied to actual work.

### 9.4 lacasadelbombero.app

**Category:** Public project  
**Visual metaphor:** Public/commercial/community building  
**Confidential:** No, subject to project-specific restrictions

Case study can include:

- screenshots;
- live link;
- implementation details;
- stack;
- problem;
- outcome.

### 9.5 FixedAI

**Category:** Completed unreleased product  
**Visual metaphor:** Startup/small modern office  
**Status:** Finished, never released

The case study should explicitly distinguish:

> completed product

from:

> publicly launched product.

There is nothing wrong with showcasing an unreleased project as long as the status is clear.

### 9.6 DepGuard

**Category:** Personal/public technical project  
**Visual metaphor:** Security/technology building

Core positioning:

> Application for searching and investigating CVEs / dependency security information.

Where possible, expose:

- live demo;
- source repository;
- technical architecture;
- search workflow;
- security-data sources.

### 9.7 Fire App — Tijuana Fire Department

**Category:** Historical professional/project work  
**Approximate date:** 2018  
**Visual metaphor:** Fire station / emergency-services building

This project is valuable because it establishes career history and real-world impact.

The exact public wording, year, scope, organization relationship and available materials must be confirmed before publication.

It should not be visually treated as unimportant simply because it is older.

## 10. Civic / Non-Project Landmarks

Not every interactive destination needs to be a software project.

### City Hall — About / Resume

City Hall acts as the portfolio's personal/professional information landmark.

Content:

- Adrian Legaspi;
- Senior Software Engineer;
- concise biography;
- experience summary;
- core technology areas;
- leadership experience;
- résumé access;
- GitHub / LinkedIn placeholders.

Avoid long autobiographical text.

### Construction Site — Contact

A visibly unfinished plot represents the next project.

The site can contain:

- foundations;
- construction barriers;
- crane;
- partially built structure;
- billboard.

Billboard:

> **NEXT PROJECT**

On selection, display:

> **There's room for one more.**
>
> **Let's build something together.**

Actions:

- Email
- LinkedIn
- GitHub
- Resume

This is the primary end-of-experience CTA.

## 12. Project Building Semantics

Project importance may affect:

- model size;
- height;
- lot footprint;
- surrounding plaza;
- location;
- subtle lighting.

It must **not** become a numeric ranking of career value.

Recommended hierarchy:

### Landmark scale

- Viasat
- HR/ATS ERP

### Medium project scale

- AI Automation
- lacasadelbombero.app
- FixedAI

### Smaller/specialized scale

- DepGuard
- Fire App

This hierarchy is a visual starting point and can change after seeing the actual Kenney models.
