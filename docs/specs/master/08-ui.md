# 08 — UI: Layout, Visual System & Copy

Part of the [legaspi.dev Master Spec](../legaspi_dev_master_spec.md). Covers original sections §16–§18, §21–§23, §33, §44.

## 16. Desktop UI

Desktop layout:

```text
┌──────────────────────────────────────────────────┐
│ Header / minimal navigation                     │
├──────────────────────────────────────────────────┤
│                              │                   │
│                              │ PROJECT PANEL     │
│          3D CITY             │                   │
│                              │ Native HTML       │
│                              │                   │
│                              │                   │
└──────────────────────────────────────────────────┘
```

The project panel should:

- slide from the right;
- remain native HTML;
- have its own vertical scroll if necessary;
- not resize the 3D canvas in a jarring way;
- provide a clear close button;
- support keyboard focus.

Suggested width:

- approximately 380–480px depending on viewport;
- never consume most of a normal desktop screen.

Use transparent/soft surfaces so the UI feels connected to the colorful city without turning into game HUD chrome.

## 17. Mobile UI

Mobile is a first-class target.

The 3D city remains present.

Do not replace it with a separate 2D portfolio unless performance fallback becomes necessary.

### Selected project

Use a bottom sheet.

Initial state can expose:

- project name;
- role;
- project type;
- drag handle.

Expanded state contains the case study.

The sheet must support normal touch scrolling independently from the canvas.

When a user begins interacting with the sheet, gestures must not move the city.

### Mobile controls

Keep persistent controls minimal:

- language;
- time/theme mode;
- possibly a reset/home button.

No tiny floating icon jungle.

---

## 18. Responsive Breakpoints

Do not design purely around fixed device widths.

Behavior categories:

### Large desktop

- city + right project panel;
- full hover behavior.

### Small desktop / tablet landscape

- narrower side panel;
- reduced decorative UI;
- same city.

### Tablet portrait / phone

- bottom sheet;
- tap interactions;
- simplified labels;
- reduced shadow/effect quality where necessary.

The app must remain usable at approximately 320px CSS width.

## 21. UI Visual System

The UI should be intentionally quieter than the 3D environment.

### Principle

> The city carries the personality. The UI carries the information.

Use:

- clean typography;
- neutral surfaces;
- generous spacing;
- one primary accent;
- restrained borders;
- little or no drop-shadow excess.

shadcn/ui components must be restyled as needed.

Do not keep default component appearance just because it came from the generator.

### Typography

Use a highly readable sans-serif.

Favor one family with a small number of weights.

Avoid game fonts.

### Project technologies

Use compact badges/chips.

Avoid fake skill progress bars or percentages.

## 22. Header

The header must be minimal.

Recommended desktop content:

```text
Adrian Legaspi
Senior Software Engineer

Projects   About   Contact        EN / ES     AUTO
```

On smaller screens, collapse secondary navigation appropriately.

The header must not dominate the city.

A résumé action can live under About or remain available as a compact dedicated action depending on final composition.

## 23. Traditional Navigation Fallback

Even though buildings are the primary interaction, normal HTML navigation is required.

Reasons:

- accessibility;
- mobile usability;
- recruiters who want speed;
- direct access;
- keyboard navigation;
- SEO-friendly structure.

A `Projects` navigation control can show project names and focus the corresponding building when selected.

This is not a separate portfolio experience. It controls the same city state.

---

## 33. Loading Experience

Avoid a theatrical loading screen unless required by actual asset loading.

Preferred flow:

1. DOM shell renders immediately.
2. Name/title/header appear.
3. City loads.
4. Placeholder/skeleton is shown only if genuinely needed.
5. Primary project buildings become interactive.
6. Decorative assets may appear progressively.

If a loading label is used, keep it simple:

```text
Building the city…
```

Do not force users through an intro they cannot skip.

## 44. Suggested UI Copy

### Hero

English:

> **Adrian Legaspi**  
> Senior Software Engineer

Spanish:

> **Adrian Legaspi**  
> Senior Software Engineer

The professional title can remain in English globally if preferred for international positioning.

### City hint

English:

> Explore the city. Each landmark is something I've built.

> Explora la ciudad. Cada edificio representa algo que he construido.

Keep this hint small and dismissible or naturally unobtrusive.

### Confidential project

English:

> Internal project. Proprietary screenshots and implementation details are intentionally not published.

Spanish:

> Proyecto interno. Las capturas y los detalles propietarios de implementación no se publican intencionalmente.

English:

> **Let's build something together.**

Spanish:

> **Construyamos algo juntos.**

Final Spanish wording may be adjusted for tone.
